**Swift Package Manager for Plugin Authors**

**How to Add Swift Package Manager Compatibility to iOS and macOS Plugins**

---

**⚠️ Warning**
Flutter is migrating to **Swift Package Manager** to manage iOS and macOS native dependencies. Flutter's support of Swift Package Manager is under development. If you find a bug in Flutter's Swift Package Manager support, open an issue. Swift Package Manager support is off by default. Flutter continues to support CocoaPods.

---

### Benefits of Swift Package Manager in Flutter
- Provides access to the Swift package ecosystem. Flutter plugins can use the growing ecosystem of Swift packages!
- Simplifies Flutter installation. Swift Package Manager is bundled with Xcode. In the future, you won’t need to install Ruby and CocoaPods to target iOS or macOS.

---

### How to Enable Swift Package Manager
Flutter's Swift Package Manager support is turned off by default. To enable it:

1. Upgrade to the latest Flutter SDK:
   ```bash
   flutter upgrade
   ```
2. Enable the Swift Package Manager feature:
   ```bash
   flutter config --enable-swift-package-manager
   ```
Using the Flutter CLI to run an app migrates the project to add Swift Package Manager integration. This makes your project download the Swift packages that your Flutter plugins depend on. An app with Swift Package Manager integration requires Flutter version 3.24 or higher. To use an older Flutter version, you will need to remove Swift Package Manager integration from the app.

Flutter falls back to CocoaPods for dependencies that do not support Swift Package Manager yet.

---

### How to Disable Swift Package Manager
Plugin authors need to turn on and off Flutter's Swift Package Manager support for testing. App developers do not need to disable Swift Package Manager support unless they are running into issues.

Disabling Swift Package Manager causes Flutter to use CocoaPods for all dependencies. However, Swift Package Manager remains integrated with your project. To remove Swift Package Manager integration completely from your project, follow the "How to Remove Swift Package Manager Integration" instructions.

#### Disable for a Single Project
In the project's `pubspec.yaml` file, under the `flutter` section, set `enable-swift-package-manager` to `false` in the `config` subsection:
```yaml
flutter:
  config:
    enable-swift-package-manager: false
```
This turns off Swift Package Manager for all contributors to this project.

#### Migrate from Deprecated Syntax
If you were previously using `disable-swift-package-manager: true`, update your `pubspec.yaml` to use the new `config` section format shown above. The old syntax is deprecated and will produce an error in Flutter 3.38 and later.

#### Disable Globally for All Projects
Run the following command:
```bash
flutter config --no-enable-swift-package-manager
```
This turns off Swift Package Manager for the current user. If a project is incompatible with Swift Package Manager, all contributors need to run this command.

---

### How to Add Swift Package Manager Support to an Existing Flutter Plugin
This guide shows how to add Swift Package Manager support to a plugin that already supports CocoaPods. This ensures the plugin is usable by all Flutter projects.

Flutter plugins should support both Swift Package Manager and CocoaPods until further notice.

#### Steps to Add Swift Package Manager Support
1. Enable the Swift Package Manager feature.
2. Create a directory under the `ios`, `macos`, and/or `darwin` directories. Name this new directory the name of the platform package:
   ```
   plugin_name/
   ios/
   plugin_name/
   ```
3. Inside this new directory, create the following files/directories:
   - `Package.swift` (file)
   - `Sources` (directory)
   - `Sources/plugin_name` (directory)
4. Your plugin structure should look like this:
   ```
   plugin_name/
   ios/
   plugin_name/
     Package.swift
     Sources/
       plugin_name/
   ```
5. Use the following template in the `Package.swift` file:
   ```swift
   // swift-tools-version: 5.9
   import PackageDescription

   let package = Package(
       name: "plugin_name",
       platforms: [
           .iOS("13.0"),
           .macOS("10.15")
       ],
       products: [
           .library(name: "plugin-name", targets: ["plugin_name"])
       ],
       dependencies: [],
       targets: [
           .target(
               name: "plugin_name",
               dependencies: [],
               resources: [
                   // If your plugin requires a privacy manifest, update the PrivacyInfo.xcprivacy file.
                   // .process("PrivacyInfo.xcprivacy"),
               ]
           )
       ]
   )
   ```
6. Update the supported platforms, package, library, and target names in the `Package.swift` file.
7. If your plugin has a `PrivacyInfo.xcprivacy` file, move it to `ios/plugin_name/Sources/plugin_name/PrivacyInfo.xcprivacy` and uncomment the relevant line in the `Package.swift` file.
8. Move any resource files from `ios/Assets` to `ios/plugin_name/Sources/plugin_name` (or a subdirectory) and add them to the `Package.swift` file.
9. Move all files from `ios/Classes` to `ios/plugin_name/Sources/plugin_name`.
10. If your plugin uses Pigeon, update your Pigeon input file:
    ```dart
    swiftOut: 'ios/plugin_name/Sources/plugin_name/messages.g.swift',
    ```
11. Update the `Package.swift` file with any customizations you might need.
12. Open the `ios/plugin_name/` directory in Xcode and verify that the `Package.swift` file does not produce any warnings or errors.
13. If your `ios/plugin_name.podspec` file has CocoaPods dependencies, add the corresponding Swift Package Manager dependencies to your `Package.swift` file.
14. If your package must be linked explicitly static or dynamic (not recommended by Apple), update the product to define the type:
    ```swift
    products: [
        .library(name: "plugin-name", type: .static, targets: ["plugin_name"])
    ],
    ```
15. Update your `ios/plugin_name.podspec` to point to the new paths:
    ```ruby
    s.source_files = 'plugin_name/Sources/plugin_name/**/*.swift'
    s.resource_bundles = {'plugin_name_privacy' => ['plugin_name/Sources/plugin_name/PrivacyInfo.xcprivacy']}
    ```
16. Update resource loading from the bundle to use `Bundle.module`:
    ```swift
    #if SWIFT_PACKAGE
         let settingsURL = Bundle.module.url(forResource: "image", withExtension: "jpg")
    #else
         let settingsURL = Bundle(for: Self.self).url(forResource: "image", withExtension: "jpg")
    #endif
    ```
17. If your `.gitignore` does not include `.build/` and `.swiftpm/` directories, add them.
18. Commit your plugin's changes to your version control system.
19. Verify that the plugin still works with CocoaPods.
20. Verify that the plugin works with Swift Package Manager.

---

### Testing the Plugin
1. Disable Swift Package Manager and run the plugin's example app to ensure it works with CocoaPods.
2. Enable Swift Package Manager and run the plugin's example app to ensure it works with Swift Package Manager.
3. Open the plugin's example app in Xcode and ensure that "Package Dependencies" appears in the Project Navigator.
4. Verify that tests pass.

---

**Note:** If your plugin has native unit tests (XCTest), make sure to update them in the plugin's example app as well.

---

**Swift Package Manager برای نویسندگان پلاگین**

**چگونه پشتیبانی Swift Package Manager را به پلاگین‌های iOS و macOS اضافه کنیم**

---

**⚠️ هشدار**
فلاتر در حال مهاجرت به **Swift Package Manager** برای مدیریت وابستگی‌های بومی iOS و macOS است. پشتیبانی فلاتر از Swift Package Manager در حال توسعه است. اگر باگی در پشتیبانی فلاتر از Swift Package Manager پیدا کردید، یک ایشو باز کنید. پشتیبانی از Swift Package Manager به‌طور پیش‌فرض غیرفعال است و فلاتر همچنان از CocoaPods پشتیبانی می‌کند.

---

### مزایای Swift Package Manager در فلاتر
- دسترسی به اکوسیستم پکیج‌های Swift را فراهم می‌کند. پلاگین‌های فلاتر می‌توانند از اکوسیستم رو به رشد پکیج‌های Swift استفاده کنند!
- نصب فلاتر را ساده می‌کند. Swift Package Manager همراه با Xcode ارائه می‌شود. در آینده، نیازی به نصب Ruby و CocoaPods برای هدف قرار دادن iOS یا macOS نخواهید داشت.

---

### نحوه فعال‌سازی Swift Package Manager
پشتیبانی فلاتر از Swift Package Manager به‌طور پیش‌فرض غیرفعال است. برای فعال‌سازی:
1. به آخرین نسخه SDK فلاتر ارتقا دهید:
   ```bash
   flutter upgrade
   ```
2. ویژگی Swift Package Manager را فعال کنید:
   ```bash
   flutter config --enable-swift-package-manager
   ```
استفاده از Flutter CLI برای اجرای یک اپ، پروژه را برای افزودن یکپارچگی Swift Package Manager مهاجرت می‌دهد. این کار باعث می‌شود پروژه شما پکیج‌های Swift مورد نیاز پلاگین‌های فلاتر را دانلود کند. یک اپ با یکپارچگی Swift Package Manager به نسخه فلاتر 3.24 یا بالاتر نیاز دارد. برای استفاده از نسخه‌های قدیمی‌تر فلاتر، باید یکپارچگی Swift Package Manager را از اپ حذف کنید.

فلاتر برای وابستگی‌هایی که هنوز از Swift Package Manager پشتیبانی نمی‌کنند، به CocoaPods بازگشت می‌کند.

---

### نحوه غیرفعال‌سازی Swift Package Manager
نویسندگان پلاگین‌ها باید برای تست، پشتیبانی فلاتر از Swift Package Manager را فعال و غیرفعال کنند. توسعه‌دهندگان اپ نیازی به غیرفعال‌سازی پشتیبانی Swift Package Manager ندارند، مگر اینکه با مشکلاتی مواجه شوند.

غیرفعال‌سازی Swift Package Manager باعث می‌شود فلاتر از CocoaPods برای همه وابستگی‌ها استفاده کند. با این حال، Swift Package Manager همچنان با پروژه شما یکپارچه باقی می‌ماند. برای حذف کامل یکپارچگی Swift Package Manager از پروژه، دستورالعمل‌های "نحوه حذف یکپارچگی Swift Package Manager" را دنبال کنید.

#### غیرفعال‌سازی برای یک پروژه خاص
در فایل `pubspec.yaml` پروژه، در بخش `flutter`، مقدار `enable-swift-package-manager` را در زیربخش `config` روی `false` تنظیم کنید:
```yaml
flutter:
  config:
    enable-swift-package-manager: false
```
این کار Swift Package Manager را برای همه مشارکت‌کنندگان در این پروژه غیرفعال می‌کند.

#### مهاجرت از سینتکس منسوخ
اگر قبلاً از `disable-swift-package-manager: true` استفاده می‌کردید، فایل `pubspec.yaml` خود را به فرمت جدید بخش `config` نشان داده شده در بالا به‌روزرسانی کنید. سینتکس قدیمی منسوخ شده و در فلاتر 3.38 و نسخه‌های بعد خطا ایجاد می‌کند.

#### غیرفعال‌سازی به‌طور جهانی برای همه پروژه‌ها
دستور زیر را اجرا کنید:
```bash
flutter config --no-enable-swift-package-manager
```
این کار Swift Package Manager را برای کاربر فعلی غیرفعال می‌کند. اگر پروژه‌ای با Swift Package Manager سازگار نیست، همه مشارکت‌کنندگان باید این دستور را اجرا کنند.

---

### نحوه افزودن پشتیبانی Swift Package Manager به یک پلاگین فلاتر موجود
این راهنما نشان می‌دهد چگونه پشتیبانی Swift Package Manager را به یک پلاگین که قبلاً از CocoaPods پشتیبانی می‌کند، اضافه کنید. این کار اطمینان می‌دهد که پلاگین برای همه پروژه‌های فلاتر قابل استفاده است.

پلاگین‌های فلاتر باید تا اطلاع ثانوی از هر دو Swift Package Manager و CocoaPods پشتیبانی کنند. پذیرش Swift Package Manager تدریجی خواهد بود. پلاگین‌هایی که از CocoaPods پشتیبانی نمی‌کنند، توسط پروژه‌هایی که هنوز به Swift Package Manager مهاجرت نکرده‌اند، قابل استفاده نخواهند بود. پلاگین‌هایی که از Swift Package Manager پشتیبانی نمی‌کنند، ممکن است برای پروژه‌هایی که مهاجرت کرده‌اند، مشکل ایجاد کنند.

#### مراحل افزودن پشتیبانی Swift Package Manager
1. ویژگی Swift Package Manager را فعال کنید.
2. یک دایرکتوری زیر دایرکتوری‌های `ios`، `macos` و/یا `darwin` ایجاد کنید. نام این دایرکتوری جدید را نام پکیج پلتفرم بگذارید:
   ```
   plugin_name/
   ios/
   plugin_name/
   ```
3. در این دایرکتوری جدید، فایل‌ها/دایرکتوری‌های زیر را ایجاد کنید:
   - `Package.swift` (فایل)
   - `Sources` (دایرکتوری)
   - `Sources/plugin_name` (دایرکتوری)
4. ساختار پلاگین شما باید شبیه به این باشد:
   ```
   plugin_name/
   ios/
   plugin_name/
     Package.swift
     Sources/
       plugin_name/
   ```
5. از قالب زیر در فایل `Package.swift` استفاده کنید:
   ```swift
   // swift-tools-version: 5.9
   import PackageDescription

   let package = Package(
       name: "plugin_name",
       platforms: [
           .iOS("13.0"),
           .macOS("10.15")
       ],
       products: [
           .library(name: "plugin-name", targets: ["plugin_name"])
       ],
       dependencies: [],
       targets: [
           .target(
               name: "plugin_name",
               dependencies: [],
               resources: [
                   // اگر پلاگین شما به مانیفست حریم خصوصی نیاز دارد، فایل PrivacyInfo.xcprivacy را به‌روزرسانی کنید.
                   // .process("PrivacyInfo.xcprivacy"),
               ]
           )
       ]
   )
   ```
6. پلتفرم‌های پشتیبانی‌شده، نام پکیج، کتابخانه و هدف را در فایل `Package.swift` به‌روزرسانی کنید.
7. اگر پلاگین شما فایل `PrivacyInfo.xcprivacy` دارد، آن را به مسیر `ios/plugin_name/Sources/plugin_name/PrivacyInfo.xcprivacy` منتقل کنید و خط مربوطه را در فایل `Package.swift` فعال کنید.
8. فایل‌های منبع را از `ios/Assets` به `ios/plugin_name/Sources/plugin_name` (یا زیردایرکتوری) منتقل کنید و آنها را به فایل `Package.swift` اضافه کنید.
9. همه فایل‌ها را از `ios/Classes` به `ios/plugin_name/Sources/plugin_name` منتقل کنید.
10. اگر پلاگین شما از Pigeon استفاده می‌کند، فایل ورودی Pigeon را به‌روزرسانی کنید:
    ```dart
    swiftOut: 'ios/plugin_name/Sources/plugin_name/messages.g.swift',
    ```
11. فایل `Package.swift` را با هرگونه سفارشی‌سازی مورد نیاز به‌روزرسانی کنید.
12. دایرکتوری `ios/plugin_name/` را در Xcode باز کنید و فایل `Package.swift` را بررسی کنید تا مطمئن شوید Xcode هیچ هشدار یا خطایی تولید نمی‌کند.
13. اگر فایل `ios/plugin_name.podspec` شما وابستگی‌های CocoaPods دارد، وابستگی‌های متناظر Swift Package Manager را به فایل `Package.swift` اضافه کنید.
14. اگر پکیج شما باید به‌طور صریح استاتیک یا دینامیک لینک شود (توصیه نمی‌شود)، محصول را برای تعریف نوع به‌روزرسانی کنید:
    ```swift
    products: [
        .library(name: "plugin-name", type: .static, targets: ["plugin_name"])
    ],
    ```
15. فایل `ios/plugin_name.podspec` را برای اشاره به مسیرهای جدید به‌روزرسانی کنید:
    ```ruby
    s.source_files = 'plugin_name/Sources/plugin_name/**/*.swift'
    s.resource_bundles = {'plugin_name_privacy' => ['plugin_name/Sources/plugin_name/PrivacyInfo.xcprivacy']}
    ```
16. بارگذاری منابع از باندل را برای استفاده از `Bundle.module` به‌روزرسانی کنید:
    ```swift
    #if SWIFT_PACKAGE
         let settingsURL = Bundle.module.url(forResource: "image", withExtension: "jpg")
    #else
         let settingsURL = Bundle(for: Self.self).url(forResource: "image", withExtension: "jpg")
    #endif
    ```
17. اگر `.gitignore` شما شامل دایرکتوری‌های `.build/` و `.swiftpm/` نیست، آنها را اضافه کنید.
18. تغییرات پلاگین را به سیستم کنترل نسخه خود کامیت کنید.
19. تأیید کنید که پلاگین همچنان با CocoaPods کار می‌کند.
20. تأیید کنید که پلاگین با Swift Package Manager کار می‌کند.

### تست پلاگین
1. Swift Package Manager را غیرفعال کنید و اپ مثال پلاگین را اجرا کنید تا مطمئن شوید با CocoaPods کار می‌کند.
2. Swift Package Manager را فعال کنید و اپ مثال پلاگین را اجرا کنید تا مطمئن شوید با Swift Package Manager کار می‌کند.
3. اپ مثال پلاگین را در Xcode باز کنید و مطمئن شوید که "Package Dependencies" در ناوبری پروژه نمایش داده می‌شود.
4. تأیید کنید که تست‌ها با موفقیت اجرا می‌شوند.
